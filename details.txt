AI Learning Project Plan (Supabase-First)

Project Goal
- Build a practical web app for Dad to learn AI skills through daily guided practice.
- Make it ready for multiple users from day one in case friends join.
- Use Supabase backend now (auth + progress data), then build frontend next.
- Keep deployment simple: static frontend + Supabase cloud backend.

Core Principles
- Practical over theoretical: each lesson should produce usable work output.
- Reliability-first: teach verification and critical use of AI.
- Progressive: each lesson unlocks after previous completion.
- Scalable from start: user accounts and per-user progress in database.

Target Learning Areas
1. Project planning and management
2. Policy development and analysis
3. Financial management
4. Monitoring and evaluation (M&E)
5. Research data collection and analysis

Recommended Architecture
- Frontend: HTML + CSS + JavaScript
- Backend: Supabase (PostgreSQL + Auth + Row Level Security)
- Lesson content source: JSON files first, optional move to DB later
- Hosting: Netlify / Vercel / GitHub Pages

Auth Recommendation (Honest Best Option)
- Enable both:
  1) Email + password
  2) Google sign-in
- Why:
  - Google is easiest for most users.
  - Email/password is fallback if someone has no Google account.
- Optional later: add email magic link (passwordless) after launch.

Supabase Setup Directions (Step-by-Step)

Step 1: Create project
1. Go to supabase.com and create a new project.
2. Choose region close to users.
3. Save these values safely:
   - Project URL
   - anon public key
   - service_role key (never expose in frontend)

Step 2: Configure authentication
1. In Supabase dashboard: Authentication -> Providers.
2. Enable Email provider (email/password).
3. Enable Google provider.
4. For Google provider:
   - Create OAuth credentials in Google Cloud Console.
   - Add authorized redirect URL from Supabase provider page.
   - Paste Google Client ID and Client Secret into Supabase.
5. In Authentication -> URL Configuration:
   - Set Site URL to your deployed frontend URL.
   - Add local dev URL (example: http://localhost:5500).
   - Add production callback URLs as needed.

Step 3: Run database schema SQL
1. Open SQL Editor in Supabase.
2. Run the full SQL schema from the "Schema SQL" section below.
3. Confirm tables and policies are created.

Step 4: Validate auth and RLS
1. Create one test user (email/password).
2. Test Google sign-in.
3. Ensure user A cannot read/write user B progress records.

Step 5: Prepare frontend config
1. Frontend should only use:
   - SUPABASE_URL
   - SUPABASE_ANON_KEY
2. Never put service_role key in frontend.

Schema SQL (Create Tables + Indexes + Triggers + RLS)

-- Extensions
create extension if not exists pgcrypto;

-- Profiles table linked to auth.users
create table if not exists public.profiles (
  id uuid primary key references auth.users(id) on delete cascade,
  full_name text,
  avatar_url text,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

-- Curriculum table (optional now, useful later)
create table if not exists public.curriculum_lessons (
  id text primary key,
  week int not null check (week between 1 and 4),
  day int not null check (day between 1 and 28),
  area text not null,
  title text not null,
  objective text not null,
  concept text not null,
  tool text not null,
  tool_quick_start text not null,
  prompt text not null,
  tips jsonb not null default '[]'::jsonb,
  practice_task text not null,
  reliability_checks jsonb not null default '[]'::jsonb,
  reflection_prompts jsonb not null default '[]'::jsonb,
  unlock_after text,
  is_active boolean not null default true,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create unique index if not exists curriculum_lessons_week_day_uniq
  on public.curriculum_lessons(week, day);

-- Per-user lesson progress
create table if not exists public.lesson_progress (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  lesson_id text not null,
  status text not null default 'not_started'
    check (status in ('not_started', 'in_progress', 'completed')),
  completed_at timestamptz,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique(user_id, lesson_id)
);

create index if not exists lesson_progress_user_idx
  on public.lesson_progress(user_id);

create index if not exists lesson_progress_user_status_idx
  on public.lesson_progress(user_id, status);

-- Per-user reflections/notes
create table if not exists public.lesson_reflections (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  lesson_id text not null,
  reflection_text text,
  output_excerpt text,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique(user_id, lesson_id)
);

create index if not exists lesson_reflections_user_idx
  on public.lesson_reflections(user_id);

-- Per-user streak/summary cache (optional but useful)
create table if not exists public.user_learning_stats (
  user_id uuid primary key references auth.users(id) on delete cascade,
  current_streak int not null default 0,
  longest_streak int not null default 0,
  total_completed int not null default 0,
  last_completed_on date,
  updated_at timestamptz not null default now()
);

-- Auto update timestamp function
create or replace function public.set_updated_at()
returns trigger as $$
begin
  new.updated_at = now();
  return new;
end;
$$ language plpgsql;

-- Attach updated_at trigger helper
drop trigger if exists trg_profiles_updated_at on public.profiles;
create trigger trg_profiles_updated_at
before update on public.profiles
for each row execute function public.set_updated_at();

drop trigger if exists trg_curriculum_lessons_updated_at on public.curriculum_lessons;
create trigger trg_curriculum_lessons_updated_at
before update on public.curriculum_lessons
for each row execute function public.set_updated_at();

drop trigger if exists trg_lesson_progress_updated_at on public.lesson_progress;
create trigger trg_lesson_progress_updated_at
before update on public.lesson_progress
for each row execute function public.set_updated_at();

drop trigger if exists trg_lesson_reflections_updated_at on public.lesson_reflections;
create trigger trg_lesson_reflections_updated_at
before update on public.lesson_reflections
for each row execute function public.set_updated_at();

drop trigger if exists trg_user_learning_stats_updated_at on public.user_learning_stats;
create trigger trg_user_learning_stats_updated_at
before update on public.user_learning_stats
for each row execute function public.set_updated_at();

-- Create profile and stats automatically on signup
create or replace function public.handle_new_user()
returns trigger as $$
begin
  insert into public.profiles (id, full_name)
  values (new.id, coalesce(new.raw_user_meta_data->>'full_name', ''))
  on conflict (id) do nothing;

  insert into public.user_learning_stats (user_id)
  values (new.id)
  on conflict (user_id) do nothing;

  return new;
end;
$$ language plpgsql security definer;

drop trigger if exists on_auth_user_created on auth.users;
create trigger on_auth_user_created
after insert on auth.users
for each row execute function public.handle_new_user();

-- Enable RLS
alter table public.profiles enable row level security;
alter table public.curriculum_lessons enable row level security;
alter table public.lesson_progress enable row level security;
alter table public.lesson_reflections enable row level security;
alter table public.user_learning_stats enable row level security;

-- Profiles policies
drop policy if exists "Profiles are viewable by owner" on public.profiles;
create policy "Profiles are viewable by owner"
on public.profiles for select
using (auth.uid() = id);

drop policy if exists "Profiles are updatable by owner" on public.profiles;
create policy "Profiles are updatable by owner"
on public.profiles for update
using (auth.uid() = id)
with check (auth.uid() = id);

-- Curriculum policies (readable by authenticated users)
drop policy if exists "Curriculum readable by authenticated users" on public.curriculum_lessons;
create policy "Curriculum readable by authenticated users"
on public.curriculum_lessons for select
to authenticated
using (is_active = true);

-- lesson_progress policies

using (auth.uid() = user_id);

with check (auth.uid() = user_id);

drop policy if exists "Users update own progress" on public.lesson_progress;
create policy "Users update own progress"

Auth Flow Decision for Frontend
- Implement these on day one:
  1) Sign up with email/password
  2) Login with email/password
  3) Continue with Google
  4) Logout
- Session persistence should be handled by Supabase JS client.

Lesson Locking Logic
- w1d1 unlocked by default for all users.
- Lesson is unlocked when previous lesson status = completed for current user.
- Lock logic runs from per-user records in lesson_progress.

Simple Config Note
- This project is using a direct static JS config file for the Supabase URL and anon key.
- That keeps the app simple and works without adding a build tool.
- The `.env` file is kept locally for reference and secret handling, but the browser app reads from `assets/js/config.js`.
